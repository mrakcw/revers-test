# Исполнитель автоматизации Cita

Бот открывает портал в Firefox через Playwright; расширение и popup не загружаются. Основной перенесенный сценарий находится в `src/portal-automation.js`, браузерный адаптер — в `src/playwright-runner.js`.

## Запуск

1. Создайте `bot/.env` и задайте `TELEGRAM_BOT_TOKEN`.
2. В каталоге `bot` установите Firefox для Playwright: `npx playwright install firefox`.
3. Запустите бота командой `npm start`.
4. В Telegram отправьте `/run`, выберите демо-клиента для короткой проверки офисов; после результата нажмите «Проверить даты» и выберите офис. Команда `/stop` закроет Firefox.

Тестовые данные клиентов задаются в `bot/test-data.js`.

Другой модуль может вызывать `startAutomation(payload, onEvent, { targetUrl, beforeNavigate })` из `src/automation.js`; объект запуска предоставляет `page`, `context`, `stop()` и `close()`. `beforeNavigate` вызывается до перехода на целевую страницу и используется для проверки испанской геолокации IP.

`LOCAL_TEST_MODE` остается включенным в тестовой сборке: режим офисов возвращает варианты на странице офисов; режим дат продолжает до доступных дат/времени и останавливается до выбора слота, CAPTCHA/SMS и подтверждения записи. После страницы офисов выбранный офис берется из payload; офис на странице процедуры не выбирается. При отсутствии записей повторный круг не запускается. Доступ проверяется вызывающим модулем бота до `startAutomation`; исполнитель не проверяет права и не обращается к API расширения. Для рабочего режима обработчик бота может вернуть код через событие `code_required`.

Playwright bridge внедряет исходный сценарий только в верхний frame и после `DOMContentLoaded`, как content script расширения с настройками manifest по умолчанию. Портал может использовать корень `/icpplus` или `/icpco`; фактические страницы соответствуют сегментам `citar`, `acInfo`, `acEntrada`, `acValidarEntrada`, `acCitar` (включая варианты `acCitarB`). Сервер добавляет `;jsessionid=...` к сегменту пути, например `/icpplus/acInfo;jsessionid=...`; это не query string. Сопоставление страниц игнорирует корень приложения и принимает необязательный `;jsessionid`. `checkPageStatus()` сразу читает `document.body`, а Playwright init scripts сами запускаются раньше и во всех frame.

Перед каждым действием runner ждёт `document.readyState === "complete"`, затем целевые элементы и необходимые inline-функции портала (`envia`, `enviar` и обработчики выбора услуги). Только после их готовности начинается исходная пауза 4,5/4,8 секунды; при незагрузившемся известном экране действие не выполняется, ожидание завершается ошибкой через 30 секунд. После действия есть короткая пауза для same-document обработчиков; после полной навигации новый документ начинает тот же цикл готовности.

Из логов исключены только сообщения CORS, в которых страница пытается загрузить ресурс `chrome-extension://` (Firefox не обслуживает Chrome extension scheme). Остальные ошибки JavaScript и сетевые ошибки продолжают выводиться.

Bridge и обработчики установлены на весь `BrowserContext`, а не только на первую страницу: при открытии порталом новой вкладки/окна сценарий и диагностика продолжаются на новой странице. Исходник расширения встраивается как обычный код в init script; `eval()` не используется, поскольку Firefox CSP может блокировать его на странице портала. CSP-сценарий с синтетическими страницами проверен до локальной границы CAPTCHA.

## TLS диагностика

Не отключайте проверку сертификата через `ignoreHTTPSErrors`. Сервер отдаёт конечный `*.administracionelectronica.gob.es` с issuer `RapidSSL TLS RSA CA G1`, но не отдаёт intermediate. В чистом профиле Firefox Playwright это вызывало `SEC_ERROR_UNKNOWN_ISSUER`; прикреплённый снимок DevTools показывал `about:certerror?...nssBadCert...` и передачу 0 B, то есть отказ происходил до HTTP-ответа. Проверенный intermediate от DigiCert лежит в `certs/RapidSSLTLSRSACAG1.crt.pem`; runner устанавливает его только в свой Firefox через policy `Certificates.Install`, без отключения TLS-проверки и без импорта в системное хранилище. После этого прямая навигация и живой тестовый проход прошли TLS.

Первый живой проход с демо payload прошёл ввод данных на `acEntrada`, `acValidarEntrada` и дошёл до `acCitarB`; портал ответил состоянием `no_slots`. Бот отправляет финальный ответ и закрывает Firefox на этом исходе. Список офисов в этой попытке не вернулся, поэтому получение офисов/дат ещё требует живого прогона, когда портал покажет варианты. Локальная логика выбора даты, office result и тестовая граница проверялись отдельно на синтетических DOM-страницах.

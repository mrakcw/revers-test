# Cita: состав тестового исполнительного модуля

Этот документ фиксирует итоговые файлы сборки Telegram-бота в `bot/` внутри `revers-test`. Каталог является тестовой миграцией; перенос в основной проект выполняется отдельно после приемки. Исполнитель работает без Chrome-расширения, popup, mock API и собственной авторизации: вызывающий модуль передает уже разрешенный payload.

## Telegram-процесс

1. `/run` предлагает выбрать демо-клиента и запускает короткий проход до списка доступных офисов. Запуск отображается одним сообщением, которое обновляется по навигации: этапы 1/6–6/6 соответствуют страницам портала; остановка редактирует это же сообщение.
2. Если портал вернул хотя бы один офис, сообщение со списком получает кнопку «Проверить даты».
3. Нажатие показывает отдельные кнопки офисов из первого результата. Выбор офиса запускает сценарий дат с `checkMode: "dates"`, `offices: [selectedOffice.id]` и `officeMode: "strict"`.
4. Пустой результат офисов не получает кнопку продолжения. Результат привязан к чату и одноразовому токену; устаревшие callback-и отклоняются.
5. Текст `En este momento no hay citas disponibles` учитывается только на шестой странице `acCitar`/`acCitarB` и только внутри `#mensajeInfo .mf-msg__info`; он возвращается в чат как итоговый результат, после чего Firefox закрывается. Завершение списка офисов/дат также закрывает Firefox. `/stop` закрывает активный запуск и редактирует сообщение прогресса.

## Файлы, необходимые для исполнения

| Файл | Назначение |
| --- | --- |
| `src/index.js` | Создает grammY-бота, конфигурацию и reconnect-сервис; подключает команды и корректно останавливает браузер при завершении процесса. |
| `src/automation-section.js` | Telegram UI и callback-и: выбор клиента, последовательность «офисы → даты → офис», защита от повторного/чужого callback-а, одно редактируемое сообщение с этапами 1/6–6/6 и запуск/остановка. В основной интеграции тестовые клиентские кнопки заменяются передачей payload от бизнес-модуля. |
| `src/automation.js` | Проверяет форму payload, предоставляет `startAutomation`, хранит активные запуски по чату и завершает их. Авторизации и API расширения здесь нет. |
| `src/playwright-runner.js` | Запускает Firefox persistent context, устанавливает TLS intermediate через Firefox policy, внедряет сценарий и соединяет события страницы с Node.js/Telegram. |
| `src/portal-automation.js` | Перенесенная логика расширения: ожидание готовности DOM, шаги портала, заполнение полей, сбор результатов офисов/дат и события завершения. `LOCAL_TEST_MODE` оставляет безопасную тестовую границу перед CAPTCHA/SMS/подтверждением записи. |
| `src/reconnect.js` | Проверяет/обеспечивает испанский выход в сеть перед начальной навигацией. |
| `test-data.js` | Демо payload для локальной тестовой команды `/run`; не является источником данных для итоговой бизнес-интеграции. |
| `package.json`, `package-lock.json` | Скрипты запуска и зафиксированные зависимости Node.js, grammY и Playwright. |
| `certs/RapidSSLTLSRSACAG1.crt.pem` | Intermediate-сертификат, необходимый Firefox для проверки TLS-цепочки портала в этой тестовой среде. |

## Вспомогательные и локальные файлы

- `README.md` и `MIGRATION.md` — запуск и детали миграции/диагностики; не импортируются приложением.
- `.env` — секрет Telegram и локальные параметры. Не переносить с секретами и не добавлять в репозиторий; в целевой среде создать отдельно.
- `data/` — локальное состояние/временные данные, если они создаются при работе; переносить только при подтвержденной необходимости.
- `Certificate for _.administracionelectronica.gob.es.htm` и соседний каталог `_files` — сохраненная страница сертификата для диагностики, не нужны для запуска.
- `node_modules/` — устанавливаемые зависимости, не переносить; выполнить `npm ci`.

## Контракт интеграции

Основной модуль вызывает `startAutomation(payload, onEvent, { targetUrl, beforeNavigate })` из `src/automation.js`. Payload должен содержать данные заявителя, числовой `procedure`, список строковых ID офисов и, для тестового процесса, `checkMode`. Для выбранного офиса исполнитель передает один ID и `officeMode: "strict"`. `onEvent` принимает события результата/статуса/ошибок; возвращаемое значение используется bridge для ожидаемого ответа, например кода подтверждения в рабочем режиме. Проверка доступа и получение пользовательского payload остаются выше этого модуля.

Для реального подключения нужно заменить только демо-поток в `src/automation-section.js` на прием разрешенного payload от бота. Сохранить поэтапный результат офисов, проверку принадлежности callback-а чату, выбор ID из полученного списка и передачу выбранного ID в сценарий дат. Перед production необходимо отдельно снять `LOCAL_TEST_MODE` только после согласования обработчиков CAPTCHA/SMS и подтверждения записи.

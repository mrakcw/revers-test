# План миграции сценария Cita в исполнительный модуль Telegram-бота

## Цель и границы

Сначала довести до проверяемого результата изолированную сборку `revers-test/bot`, используя стабильное Chrome-расширение из корня `revers-test` как эталон сценария. Перенос в основной проект выполнять только после контрольного прохода тестовой сборки.

Исполнитель не оформляет запись и не решает CAPTCHA. Он однократно проходит нужные страницы, возвращает результат вызывающему модулю и сохраняет журнал выполнения. Автоматический цикл повторов после ответа «нет записей» убрать. Запуск должен работать как из меню Telegram, так и по вызову другого модуля; во время проверки бот продолжает обслуживать остальные команды.

В рамках текущей работы редактируется только `revers-test`. Файлы основного проекта подключаются как справочные образцы; `.env`, токены, рабочую базу и реальные персональные данные в тестовый каталог не копировать.

## Что уже известно

- Корень `revers-test` — донор: `content.js`, `background.js`, `manifest.json`, `popup.js`, `procedures.js` и тестовые файлы расширения.
- `revers-test/bot` — отдельная Node.js/Playwright/grammY сборка для миграции; popup и ввод данных через форму расширения должны быть удалены из конечного исполнительного модуля.
- Payload передаёт другой модуль. Контракт должен быть согласован с данными клиента бота.
- Данные в `revers-test/bot/test-data.js` подтверждены пользователем как демонстрационные.
- Браузерный адаптер уже использует Firefox persistent context, проверку испанского IP и перенос сценария в `bot/src/portal-automation.js`.
- Синтетический маршрут до локальной CAPTCHA-границы проверен; после правки инжектор также проходит синтетические страницы с ограничительной CSP без `eval()`.
- TLS исправлен для изолированного Firefox-профиля через проверенный intermediate DigiCert и Firefox policy `Certificates.Install`; `ignoreHTTPSErrors` не включен.
- Первый живой проход с демо payload достиг `/icpco/acEntrada`, прошёл `acValidarEntrada`, затем получил от портала `no_slots` на `/icpco/acCitarB`. Маршруты поддерживают `/icpco` и `/icpplus`, включая `;jsessionid` в сегменте пути. Обработчик сообщает об отсутствии записей и закрывает Firefox. Получение списка офисов/дат в живом проходе ещё не подтверждено.

## Эталонный порядок страниц

Наблюдаемая последовательность переходов:

1. `https://icp.administracionelectronica.gob.es/icpplustiem/index.html`
2. `https://icp.administracionelectronica.gob.es/icpplus/citar?p=46&locale=es` (query зависит от провинции)
3. `https://icp.administracionelectronica.gob.es/icpplus/acInfo`
4. `https://icp.administracionelectronica.gob.es/icpplus/acEntrada`
5. `https://icp.administracionelectronica.gob.es/icpplus/acValidarEntrada`
6. `https://icp.administracionelectronica.gob.es/icpplus/acCitar`

Для проверки использованы пользовательские фрагменты DevTools: провинция — `select#form`, процедура — `select#tramiteGrupo\\[0\\]`, согласия/переход — `#btnEntrar`, данные — `#txtIdCitado` и `#txtDesCitado`, запрос записи — `#btnEnviar[value="Solicitar Cita"]`, офис — `select#idSede` с кнопкой `#btnSiguiente`. Стартовый адрес фактически `/icpplustiem/index.html`.

Между переходами 2 и 3 портал временно добавляет параметры URL; после загрузки адрес очищается до стандартного. Это переход/редирект в рамках той же страницы сценария, а не дополнительный шаг. Исполнитель должен логировать фактический URL и распознавать состояние по DOM, не считать каждый вариант query отдельной стадией.

Логические действия, заданные пользователем:

| Шаг | Действие | Правило |
|---|---|---|
| 1 | Выбор провинции | Использовать провинцию из payload. |
| 2 | Выбор услуги/процедуры | Использовать ID услуги из payload. Офис на этом шаге не выбирать; его поле оставить пустым. |
| 3 | Условия и подтверждение согласия | Сверить точный DOM и текст согласия с донором/обезличенной страницей; отметить только обязательное согласие и продолжить. |
| 4 | NIE/паспорт и имя | Заполнить документ согласно типу документа и имя клиента. |
| 5 | Кнопка `Solicitar Cita` | Нажать один раз и дождаться следующего состояния. |
| 6 | Доступные офисы | Вернуть список доступных офисов или результат «нет в наличии»; короткая функция заканчивается. Выбор офиса не выполнять на шаге 2. |
| 7 | Телефон и email | Только полный сценарий и только если эти поля переданы и прошли валидацию. |
| 8 | Даты/время и CAPTCHA | Полная функция извлекает доступные дату/время. CAPTCHA не решать, финальное подтверждение записи не нажимать. |

Связь логических шагов 1–8 с URL выше уточнить по DOM контрольных точек при ручном проходе. URL-список фиксирует переходы; логические номера — бизнес-действия, поэтому промежуточная загрузка или очистка query не должна менять их нумерацию.

## Контракт исполнительного модуля

- Вход: `dataForCheck` либо payload, полученный параметром вызова. Валидация должна привести его к единому объекту с полями клиента, документа, `city`/провинции, `procedure`/услуги, `offices`, `officeMode`, `tel`, `email`, `birthYear`, `country`.
- Источник: сначала переданный payload; при его отсутствии — тестовый выбор из демонстрационного набора. Позже адаптер `client-request` преобразует запись SQLite в тот же контракт.
- Короткая функция: `check_available_cita` — выполнить один проход до контрольной точки шага 6 и вернуть `{status, offices, message}` либо структурированный результат «нет в наличии».
- Полная функция: `check_available_date` — выполнить один проход до шага 8; до запуска проверить наличие обязательных для полного сценария телефона и email; вернуть `{status, offices, dates/times, message}`.
- Результаты обеих функций вернуть вызывающему коду и отправить в чат одним новым сообщением. Ошибку TLS, геолокации, навигации, неизвестный экран и таймаут не подменять ответом «нет записей».
- Один запуск — один результат. Не запускать повторный круг автоматически; ограничивать параллельные браузерные запуски согласованной политикой модуля.
- Журналировать этап, URL, результат, длительность и ошибку без записи полного NIE/паспорта, телефона, email, токена, cookies или CAPTCHA. Сохранение результата в БД выполнять через существующий сервис SQLite после подтверждения его схемы.
